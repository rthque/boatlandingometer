# Boatlandingometer

Tide graph for Dieppe, drawn against the jacket structure and boat landing of an
offshore wind turbine, so a crew can read at a glance whether a transfer is
feasible at a given time.

## Stack

Static single-page app — plain Vite 7 + React 19 + TanStack Router (client
only), Tailwind 4, shadcn/ui. **There is no server and no build step that needs
one.** `npm run build` emits a `dist/` folder of static files.

The project used to be a Lovable-generated TanStack Start app deployed to
Cloudflare Workers. That is gone: no `@tanstack/react-start`, no Nitro, no
`@lovable.dev/*`, no server functions. Don't reintroduce them — SSR would break
the GitHub Pages deployment.

## Commands

```bash
npm run dev       # dev server -> http://localhost:5173/boatlandingometer/
npm run build     # tsc --noEmit && vite build -> dist/
npm run preview   # serve the built dist/
npm run lint      # eslint (6 pre-existing shadcn fast-refresh warnings are expected)
npm run format    # prettier --write .
npm run stations  # regenerate src/lib/stations.json
```

`npm run lint` must report **0 errors**; CI fails otherwise.

## Tide data — the important part

Predictions run in the browser from harmonic constituents baked into
`src/lib/stations.json` (~12 KB, two stations: Dieppe for the site, Brest for
the French tidal coefficient reference).

That file is generated by `scripts/extract-stations.mjs` from
`@neaps/tide-database`, which is a **devDependency only**. The full database is
~24 MB; shipping it would make a static client-side build unusable. At runtime
we depend on `@neaps/tide-predictor` alone (~95 KB).

The extraction was verified bit-identical to the old server-side path across
9,217 extremes spanning 12 years — 0.000 m level difference, 0 ms time
difference. If you change how stations are extracted or predicted, re-verify
against `@neaps/tide-database`'s `nearest()` before trusting the output.

`src/lib/tides.ts` is pure synchronous computation. It is not a hook, has no
loading state, and must stay free of network calls.

## Base path

The app is served from `https://rthque.github.io/boatlandingometer/`, so
`vite.config.ts` sets `base: "/boatlandingometer/"` and `src/router.tsx` passes
`basepath: import.meta.env.BASE_URL`. Vite applies `base` in dev as well, so the
dev URL carries the same prefix. Building for a different host: set
`VITE_BASE=/`.

GitHub Pages has no SPA rewrite, so `vite.config.ts` copies `index.html` to
`404.html` at build time. Keep that plugin if you add routes.

## Deployment

Push to `main` → `.github/workflows/deploy.yml` runs lint + build and publishes
`dist/` to GitHub Pages. Nothing else to do; there is no deploy token or
third-party account involved.

## Layout notes

- `src/routes/index.tsx` is the whole UI (one route). It is large by design.
- `src/lib/views.ts` defines the FOU / BL / IRL background schemas and the WC59
  vessel overlay, with the pixel geometry that maps water height to screen
  position. Changing an image means re-deriving those numbers.
- `src/components/ui/*` is untouched shadcn — don't hand-edit, regenerate.
- Line endings are forced to LF by `.gitattributes`; without it, a Windows
  checkout with `core.autocrlf=true` makes Prettier flag every line.
